# 공개수업 당일 운영 체크리스트

돌멩홈쇼핑 · 세계 여행 특가전 — 교사용

---

## A. 수업 전날까지 (한 번만 하면 되는 준비)

- [ ] Supabase 프로젝트 생성
- [ ] `supabase/migrations/0001_init.sql` 실행
- [ ] `supabase/seed/01_session_and_products.sql` 실행 (모둠 5개 · 국가 확인)
- [ ] `supabase/seed/02_student_roster_template.sql` 의 이름을 **실제 학생 18명**으로 바꿔 실행
- [ ] `supabase/seed/03_parent_code_and_admin.sql` 에서
      - [ ] 학부모 공통 참여 코드 정하기 (예: `TRAVEL2026`)
      - [ ] 교사 계정 만들고 `admin_users` 에 등록
- [ ] `.env` 에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_SESSION_SLUG` 입력
      (`VITE_DEMO_MODE=false`, `VITE_ALLOW_DEMO_QUERY=false` 확인)
- [ ] 사이트 배포(또는 교실 노트북에서 `npm run dev -- --host` 로 같은 와이파이에 공개)
- [ ] 참여자용 주소로 **QR코드** 만들어 인쇄/슬라이드에 넣기 (주소는 `/`, `/admin` 아님)
- [ ] 각 모둠의 소개 문구·대표 사진이 정해졌다면 `travel_products` 의 `tagline`, `image_url` 수정

## B. 리허설 (수업 하루 전 또는 당일 아침)

- [ ] 교사 휴대전화 + 학생 기기 1대로 처음부터 끝까지 한 번 돌려보기
- [ ] 학생 입장 → 대기 → 구매 → 탑승권 확인
- [ ] 학부모 코드 입장 → 서로 다른 2개 선택 → 구매 확인
- [ ] `/admin` 에서 실시간 현황이 올라가는지 확인
- [ ] 결과 공개 미리보기 확인
- [ ] **리허설이 끝나면 `/admin` → `리허설 데이터 초기화` → `초기화` 입력 후 실행**
      (학생 명단은 그대로 두기 체크 유지)
- [ ] 상태가 `구매 시작 전(waiting)` 인지 확인

## C. 수업 시작 직전 (5분 전)

- [ ] 교실 와이파이 연결 확인 (학부모 기기는 데이터도 가능)
- [ ] 프로젝터에 결과 화면을 띄울 노트북 준비 (참여자 화면 `/` 을 띄워 두면 결과 공개 시 자동 전환)
- [ ] 교사 휴대전화/태블릿에 `/admin` 로그인 해 두기
- [ ] 칠판 또는 화면에 안내 띄우기
      - 접속 주소(QR)
      - 학부모 참여 코드
      - "학생은 번호와 이름을 명단 그대로 입력"
- [ ] 상태가 `구매 시작 전` 인지 마지막 확인

## D. 수업 중 진행 순서

1. 모둠별 여행 상품 발표 (이때 참여자는 미리 입장해 대기 화면을 봐도 됩니다)
2. 발표가 모두 끝나면 → `/admin` 에서 **① 구매 시작**
   - 참여자 화면이 새로고침 없이 구매 화면으로 바뀝니다
3. 구매 진행 (교사만 실시간 현황을 봅니다)
   - [ ] 참여 완료 학생 수가 18명에 가까워지는지 확인
   - [ ] 아직 안 한 학생이 있으면 기다렸다가 마감
4. → **② 구매 끝**
   - 참여자 화면: "구매가 마감되었습니다. 곧 결과를 공개합니다."
5. 관리자 화면에서 **정확한 전체 순위 확인** (여기까지는 학생에게 보이지 않습니다)
6. 공개 범위 고르기: `1위만 / TOP 2 / TOP 3 / 전체 순위`
   - 동점이 있으면 "동점으로 N개 추가 공개" 안내를 확인
   - 0장인 모둠이 있는지 확인 (부분 공개에서는 숨겨집니다)
7. **학생 화면 미리보기**로 실제 보일 화면 확인
8. **이 범위로 결과 공개** → 확인창에서 공개될 모둠·숨겨질 수·기대평 수 확인 후 공개
9. 참여자 화면과 프로젝터가 결과 화면으로 자동 전환됩니다
10. 필요하면 범위를 넓혀 가며 단계적으로 공개 (TOP 2 → TOP 3 → 전체)

## E. 마무리

- [ ] 결과 화면의 기대평을 함께 읽기
- [ ] 마무리 문구 확인: "모든 모둠이 지형과 기후를 담은 멋진 여행 상품을 완성했습니다!"
- [ ] (원한다면) 수업 후 `리허설 데이터 초기화`로 구매 기록 삭제

## 자주 생기는 상황

| 상황 | 대처 |
| --- | --- |
| 학생이 "번호와 이름이 명단과 달라요" | 명단의 이름과 정확히 같은지 확인(띄어쓰기는 무시됨). 계속 안 되면 `student_roster` 확인 |
| 학생이 실수로 다른 상품을 구매함 | 되돌릴 수 없습니다(설계상 수정 불가). 결과에 영향이 크지 않음을 안내해 주세요 |
| 학부모가 "이 기기에서는 이미 구매를 마쳤어요" | 한 기기당 1회입니다. 다른 가족 기기로 참여하도록 안내 |
| 구매를 일찍 마감했는데 남은 학생이 있음 | `/admin` → `예외 조작` → `구매 진행 중으로 되돌리기` (확인창) |
| 결과를 너무 일찍 공개함 | `예외 조작`으로 되돌릴 수 있지만, 공개 범위를 넓히는 방향으로 진행하는 편이 자연스럽습니다 |
| 인터넷이 끊김 | 화면에 안내가 뜨고 자동으로 다시 시도합니다. 이미 완료된 구매는 사라지지 않습니다 |
| 결과가 모두 0장 | "아직 집계된 여행권이 없습니다."가 표시됩니다(억지로 1위를 만들지 않음) |

## 안내해 두면 좋은 말

- "학생 고객님은 여행권 1장, 학부모 고객님은 서로 다른 상품을 고를 수 있는 여행권 2장이에요."
- "구매를 확정하면 바꿀 수 없으니 잘 생각하고 눌러 주세요."
- "누가 어떤 상품을 골랐는지는 선생님도 볼 수 없어요. 기대평도 이름 없이 보여요."
